# Contributor instructions

- Implement only the requested maintenance change. The runtime must stay an
  instruction-only worldbuilding skill with SKILL.md as the sole policy source.
- Preserve explicit user intent, approved canon, ordinary details and output format.
- Do not turn a researched ingredient into a claim that every related plot is
  empirically common. Keep evidence and editorial policy separate.
- Do not add model/version stereotypes, runtime APIs, telemetry or a large catalogue.
- Define regression expectations before editing the policy. Never weaken tests to
  obtain a pass. Test changes require separate explanation/review.
- Run the checks in CONTRIBUTING.md. Distinguish static, package, host activation,
  manually reviewed generation, and comparative efficacy results.
- Do not modify personal/global host settings, publish a GitHub repository, push,
  create a release, or claim CI passed without explicit authorization/evidence.
